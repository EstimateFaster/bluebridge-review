# 题 2 · 改版题：静态壳 + 三块新功能

> 考察重点：**自绘键盘 / 功能设计 / UI 设计 / 改版维护**　·　难度：★★★

## 背景

[`starter/`](starter/) 是由「股市大亨」裁剪而来的**静态壳工程**：

- 游戏功能已全部删除（收盘、每日任务、猜涨跌、消息、成就、存档、礼品码、颜色转换、教程、更新日志等都不在了）；
- 只保留静态页面：**首页 / 行情 / 持仓 / 股票详情 / 设置 / 关于**；
- 数据全部写死：默认现金 **80000**、固定股票与固定持仓；
- 包名：`com.bluebridge.review`。

你的任务是：**在这个静态壳上新增三块功能，并保持原有页面风格统一。**

> 先读 `starter/README.md` 跑通构建，再动手。

## 必做功能

### 1. 礼包码（重点考察：键盘自绘 + UI）

- 新增礼包码页面，入口建议放在**设置页**；
- 使用 **自绘键盘** 输入礼包码：
  - **不能使用系统输入框 / 原生键盘**；
  - 用代码绘制 3 × 4 九宫格（0–9 + 删除 + 确认），按钮自绘；
- 输入流程完整：输入显示、退格/清空、提交、成功/失败反馈；
- 兑换逻辑可以纯静态：在本地定义几个有效码（写进提交的 README 即可），**不需要联网**；
- 加分项：按键振动/音效、长按连续删除、错误抖动动画、防连点。

### 2. 颜色转换（重点考察：功能设计）

- 在设置页新增「颜色转换」入口；
- 至少 **4 套预设主题** + 「恢复默认」；
- 切换后**全局主题即时生效**（背景色、文字色、强调色等），并**持久化**（退出重进保持）；
- 加分项：支持自定义 HEK/HEX 颜色值、主题预览卡、对比度不足提示、图标颜色跟随主题；
- 注意：不能只改当前页面局部颜色，要接入工程的样式体系。

### 3. 每日任务界面（只做 UI，重点考察：UI 设计）

- 新增每日任务页面（静态数据即可，**不要求真实任务逻辑**）；
- 顶部：今日任务进度（如 3/5）；
- 列表项：任务标题、进度条、奖励、状态（未完成 / 可领取 / 已领取）；
- 至少覆盖这几种状态：进行中、可领取、已领取、空状态或全部完成状态；
- 加分项：领取动画、奖励图标、分类 tab。

## 硬性约束

- 基于 `starter/` 修改，**包名保持 `com.bluebridge.review`**；
- 不修改既有页面的视觉风格，新增页面风格需与工程统一；
- 必须能构建出 `.rpk` 并在模拟器/真机运行；
- 可复用 starter 现有资产，也可以自备，但不要引入体积过大的无关资产；
- 三个功能都要有真实可点的界面，不接受只有静态截图。

## 交付物

1. 源码目录（基于 starter）；
2. `.rpk` 构建产物；
3. 3–5 张截图（礼包码页、颜色转换页、每日任务页各至少一张）；
4. `README.md`：
   - 构建/运行方法；
   - 三块功能的入口与设计说明（特别是自绘键盘的实现思路、颜色主题怎么接入、任务状态怎么设计）；
   - **有效礼包码列表**；
   - **AI 使用说明** + **迭代日志**（至少 3 条）。

## 现场环节

- **演示**：三块功能各演示一遍 + 讲实现思路；
- **现场改动**（评审方选 1–2 项）：
  - 礼包码改成 6 位，并支持长按连续删除；
  - 主题切换后杀掉应用重启，验证持久化；
  - 每日任务列表插入一条「已完成但未领取」的数据，现场调通状态；
  - 给礼包码页加「最近一次兑换码」记忆；
  - 颜色转换增加一键「恢复默认」并验证。
- **追问**：
  - 为什么自绘键盘而不用系统输入组件？按键区尺寸怎么定的？
  - 颜色切换如何保证对比度可读？某页文字会不会看不见？
  - storage 的数据结构怎么设计？以后加新字段怎么兼容？
  - 这三块功能你会怎么排优先级？为什么？

## 环境
