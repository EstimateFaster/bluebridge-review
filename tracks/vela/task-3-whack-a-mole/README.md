# 题 3 · 完整 rpk 开发：打地鼠小游戏

> 考察重点：**完整开发能力 / 多页路由 / 玩法与反馈**　·　难度：★★★

## 题目

从零开发一个可玩的「打地鼠」小米 Vela 快应用（rpk），**单关卡**，必须使用**多页面路由**，建议引入资产。

## 功能要求

### 页面（至少 3 个路由）

1. **主页**：游戏名称/封面、开始游戏按钮、关于入口；
2. **关于页**：玩法说明、版权信息、返回；
3. **游戏页**：打地鼠主玩法 + 结算。

### 玩法

- 单关卡，倒计时制（建议 30 秒，可自定但要在 README 说明）；
- 地鼠在 3 × 3（或更大）格子里随机出现，点击命中得分；
- 时间结束进入结算：本局得分 + 最高分；
- 本地持久化历史最高分（`storage`）；
- 空点/漏打是否惩罚自定，需在 README 说明。

### 反馈与体验

- 命中要有视觉反馈（动画/闪白/锤子等），并至少再加一种反馈：**音效 / 振动**；
- 加分项：连击（combo）、金地鼠（高分）、难度随时间提升、暂停/重开、结算页重玩按钮。

### 技术约束

- Vela 快应用 rpk，设计基准 **336 × 480**（`designWidth: 336`）；
- 多页面：在 `manifest.json` 的 `router.pages` 注册至少 3 个页面；
- 状态在页面间正确传递（主页 → 游戏 → 结算 → 返回主页）；
- 必须能构建、能在模拟器或真机运行。

## 交付物

1. 源码目录；
2. `.rpk` 构建产物；
3. 3–5 张截图（主页/游戏/结算/关于）；
4. `README.md`：
   - 构建/运行方法；
   - 玩法与规则说明（时长、得分、惩罚、难度曲线）；
   - 设计说明（页面结构、状态怎么管理）；
   - **AI 使用说明** + **迭代日志**（至少 3 条）；
5. 可选：30 秒演示视频。

## 现场环节

- **演示**：完整玩一局 + 讲页面结构与实现；
- **现场改动**（评审方选 1–2 项）：
  - 倒计时从 30 秒改成 15 秒；
  - 增加「金地鼠」：出现概率更低但双倍分；
  - 调整难度曲线（地鼠刷新间隔逐秒变快）；
  - 增加「暂停/继续」功能；
  - 结算页增加「再玩一局」并正确重置状态。
- **追问**：
  - 地鼠随机怎么避免同一位置连续刷？难度怎么控制？
  - 计时器/动画在页面退出时怎么清理？
  - 页面之间状态怎么传？从结算返回主页再进游戏，状态会怎样？
  - 如果要加本地排行榜，你会怎么改数据结构？
