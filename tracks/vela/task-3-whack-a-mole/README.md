# 题 3 · 完整 rpk 开发：打地鼠

> 考察重点：**核心玩法完成度 / 多页路由 / 代码结构**　·　难度：★★

## 题目

开发一个可玩的「打地鼠」Vela 快应用（rpk），**单关卡**，使用**多页面路由**。

本页只要求把**核心玩法**做出来：界面能用即可，**不考 UI/美术**，也**不需要真的画出地鼠**——用色块、圆点、emoji、文字或几何图形都可以。

## 必须实现（核心玩法）

1. **一局有开始和结束**：倒计时制（建议 30 秒，可自定，在 README 说明）；
2. **目标随机出现**：在 3 × 3 格子里随机位置出现；
3. **点击命中**：点中目标得分，目标消失并刷新；
4. **结算**：时间结束后显示本局得分；
5. **可重新开始**：从结算页或主页能再开一局。

## 页面路由（至少 3 页）

- **主页**：开始游戏 + 关于入口；
- **关于页**：玩法说明 + 版权信息 + 返回；
- **游戏页**：核心玩法 + 结算/重开。

页面之间跳转、返回、重开流程要正常，状态不能错乱。

## 不硬性要求（随心发挥，做得好是加分项）

- UI 美观度、配色、排版、字号；
- 真实地鼠美术/图片资产——**不必真正做地鼠**，占位符即可；
- 音效、振动、命中动画；
- 最高分本地持久化；
- combo、金地鼠、难度随时间提升、暂停/继续。

## 交付物

1. 源码目录；
2. `.rpk` 构建产物；
3. 1–2 张运行截图（主页 + 游戏页即可）；
4. `README.md`：
   - 构建/运行方法；
   - 玩法与规则说明（时长、得分、刷新逻辑）；
   - **AI 使用说明** + **迭代日志**（至少 3 条）；
5. 可选：30 秒演示视频。

| 维度 | 权重 | 看什么 |

> UI、音效、资产等不单独计分；做得好会在答辩中作为加分项体现。

## 现场环节

- **演示**：完整玩一局 + 讲页面结构与实现；
- **现场改动**（评审方选 1–2 项）：
  - 倒计时从 30 秒改成 15 秒；
  - 增加「金地鼠」：出现概率更低但双倍分；
  - 刷新间隔逐秒变快；
  - 增加「暂停/继续」；
  - 结算页「再玩一局」并正确重置状态。
- **追问**：
  - 目标随机怎么避免同一位置连续刷？
  - 计时器在页面退出时怎么清理？
  - 页面之间状态怎么传递？从结算返回主页再进游戏，状态会怎样？
  - 如果要加本地排行榜，你会怎么改数据结构？
